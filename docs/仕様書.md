# プレスリリースサポートアプリ 仕様書（たたき台 v0.3）

元資料：仕様書の元となる文書.md を整理・補強したもの。`【要確認】` は未決事項（9章に一覧）。

## 1. 概要

クライアント（企業）が日時・場所・写真などを入力するとプレスリリース（ドキュメントファイル）を自動作成でき、さらに有料で取材会の企画支援・同行・投げ込み代行・記事作成・動画作成を依頼できる Web アプリ。管理者は、作成された書類と依頼内容を確認する。

- 技術前提：Python / Flask、決済は Stripe（元資料より）
- **開発環境と本番環境で、一部の部品を切り替える。本番は Google Cloud を使用する。**（忘れないための注意）

| 項目 | 開発環境 | 本番環境 |
| --- | --- | --- |
| 実行基盤 | ローカル（WSL）で `flask run` | Google Cloud【要確認】Cloud Run など |
| データベース | 【要確認】SQLite など手軽なもの | 【要確認】Cloud SQL など |
| ファイル保存（写真・Word） | ローカルフォルダ | 【要確認】Cloud Storage |
| メール | ログ出力のみ | 【要確認】実際に送信する仕組み |
| 秘密情報（Stripe キーなど） | `.env` ファイル | 【要確認】Secret Manager など |
| Stripe | テストモード | 本番モード |

※ 切り替えは、コード内に書き込まず、環境変数（設定）で行う。
- 利用者：クライアント（広報担当・中小企業など）、管理者（運営側）

## 2. 目的・背景

- プレスリリースの作り方・配り方（投げ込み）が分からない企業を支援する。
- 書類作成は無料で提供し、有料の周辺サービスで収益を得る。
- 【要確認】想定する主な顧客像（業種・規模）と、解決したい具体的な困りごと。

## 8. 非機能要件

- **セキュリティ**
  - パスワードはハッシュ化して保存する。CSRF 対策を入れる。
  - 他人の書類・注文は参照不可（所有者チェック）。
  - アップロードは MIME・拡張子・サイズに加え、画像として開けるか検証する。保存名はランダム化する。
  - 管理者はコマンドでのみ作成する。
  - Stripe の秘密鍵・Webhook シークレットは環境変数で管理し、Git に含めない（`.env` は `.gitignore`）。Webhook は署名検証する。
- **決済**：支払い確定は Webhook のみ。同じイベントを2回受けても二重処理しない（冪等性）。支払いは申込み時の前払い。返金は管理者の操作で Stripe の返金機能を使い、返金額の合計が支払額を超えないようにする。
- **書類の形式**：Word（.docx）。python-docx などで生成し、日本語フォントを指定する。文面は入力項目の差し込みのみ（AI での文章整形は第2弾）。
- **環境**：Python 3.x、Flask。開発環境と本番環境（Google Cloud）で一部の部品を切り替える（3章の表を参照）。設定は環境変数で切り替える。
- **個人情報**：電話番号・住所を扱うため、プライバシーポリシーと利用規約のページが必要。
- **テスト**：認証・アクセス制御・アップロード検証・Webhook を優先して自動テスト化する。

### 未決
1. **管理者の編集の細部**：編集後にクライアントへ通知するか、クライアントが再確認・同意してから承認する流れにするか、編集履歴（変更前後）を残すか。承認後の書類は編集不可とする想定。
2. **承認制の細部**：承認の目標期間（例：2営業日）、差し戻し・承認時にクライアントへメール通知するか。
3. **Word のテンプレート**：レイアウト（見出し、写真の配置、会社情報の入れ方）。誰がデザインするか。
4. **有料サービスの金額**：5種それぞれの固定料金（税込／税別）と、納期の目安。
5. **問い合わせ窓口と規約**：問い合わせ用メールアドレスの用意。利用規約と特定商取引法に基づく表記（返金基準を含む）のページを作るか。「着手」にする基準（管理者が進捗を更新した時点、でよいか）。
6. **退会・データ削除**：個人情報の扱い。
7. **記事作成・動画作成**：成果物の納品方法（ファイルのダウンロード／メール）、動画の制作範囲（撮影を含むか）、修正回数。
8. 【要確認】想定する主な顧客像。Google Cloud の具体的なサービス（3章の表の【要確認】）。
