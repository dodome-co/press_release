# プレスリリースサポートアプリ 仕様書（たたき台 v0.4）

元資料：仕様書の元となる文書.md を整理・補強したもの。`【要確認】` は未決事項（9章に一覧）。

## 1. 概要

クライアント（企業）が日時・場所・写真などを入力すると、管理者が仕上げたプレスリリース（Word）を受け取れる。さらに有料で取材会の企画支援・同行・投げ込み代行・記事作成・動画作成を依頼できる Web アプリ。管理者は、作成された書類と依頼内容を確認する。

- 利用者：クライアント（広報担当・中小企業など）、管理者（運営側）
- 技術前提：Python / Flask、決済は Stripe（元資料より）
- **開発環境と本番環境で、一部の部品を切り替える。本番は Google Cloud を使用する。**（忘れないための注意）

| 項目 | 開発環境 | 本番環境 |
| --- | --- | --- |
| 実行基盤 | ローカル（WSL）で `flask run` | Google Cloud の Cloud Run |
| データベース | SQLite（手軽なもの） | Cloud SQL（MySQL） |
| ファイル保存（写真・Word） | ローカルフォルダ | Cloud Storage（想定。未確認） |
| メール | ログ出力のみ | 【要確認】実際に送信する仕組み（あとで決める） |
| 秘密情報（Stripe キーなど） | `.env` ファイル | Secret Manager（想定。未確認） |
| Stripe | テストモード | 本番モード |

※ 切り替えは、コード内に書き込まず、環境変数（設定）で行う。

※ 開発の SQLite と本番の MySQL は細かい動きが違うことがある。本番に近い状態で確認するため、公開前に MySQL で動作確認する（または開発も MySQL にそろえる）。

### 書類作成の流れ

| 段階 | 流れ |
| --- | --- |
| **API 導入前**（最初のリリース） | ① クライアントが入力 → ② 日時・場所などの単純項目は、フォーマット（テンプレート）に自動で入る → ③ **要旨（前文）は管理者が書く**。書類を確認・修正する → ④ 承認すると Word で出力される |
| **API 導入後**（第2弾） | ① クライアントが入力 → ② API（AI）が要旨（前文）の**文書案**を作る → ③ 管理者が書類を確認・修正する（案を直す） → ④ 承認すると Word で出力される |

- 要旨（前文）は、どちらの段階でも最後は管理者が確認して仕上げる。違いは、最初から書くか、AI の案を直すか。
- 要旨（前文）とは、「取材してほしい内容」と「社会的意義」を含めた、リリースの冒頭の文章のこと。
- Word は、承認の時点で出力する（提出時には作らない）。

## 2. 目的・背景

- プレスリリースの作り方・配り方（投げ込み）が分からない企業を支援する。
- 書類作成は無料（1件まで）で提供し、有料の周辺サービスで収益を得る。
- 想定する主な顧客：中小企業・個人事業主（広報担当がいない、または少ない）。プレスリリースの作り方・配り方が分からない企業。

## 8. 非機能要件

- **セキュリティ**
  - パスワードはハッシュ化して保存する。CSRF 対策を入れる。
  - 他人の書類・注文は参照不可（所有者チェック）。
  - アップロードは MIME・拡張子・サイズに加え、画像として開けるか検証する。保存名はランダム化する。
  - 管理者はコマンドでのみ作成する。
  - Stripe の秘密鍵・Webhook シークレットは環境変数で管理し、Git に含めない（`.env` は `.gitignore`）。Webhook は署名検証する。
- **決済**：支払い確定は Webhook のみ。同じイベントを2回受けても二重処理しない（冪等性）。支払いは申込み時の前払い。返金は管理者の操作で Stripe の返金機能を使い、返金額の合計が支払額を超えないようにする。
- **書類の形式**：Word（.docx）。python-docx などで生成し、日本語フォントを指定する。単純項目はテンプレートに差し込み、要旨（前文）は管理者が作成する。AI（API）による要旨の文書案作成は第2弾。承認時に Word を出力する。
- **環境**：Python 3.x、Flask。開発環境と本番環境（Google Cloud）で一部の部品を切り替える（3章の表を参照）。設定は環境変数で切り替える。
- **個人情報**：電話番号・住所を扱うため、プライバシーポリシーと利用規約のページが必要。
- **設定値**：コードに書き込まず、設定で変更できるようにする。対象：無料の書類の上限（1件）、入力欄の文字数（500文字）、承認の目安（2営業日）、返金の割合。
- **テスト**：認証・アクセス制御・アップロード検証・Webhook を優先して自動テスト化する。

| 文面の作り方 | 単純項目はテンプレートに自動で入る。要旨（前文）は管理者が作成（導入後は AI の案を修正）。当初の「差し込みのみ」から変更 |
| 管理者の確認 | 承認制（承認後にクライアントがダウンロード可） |
| Word のテンプレート作成者 | 運営者が Word で雛形（.docx）を作る。デザインを変えるときは雛形を差し替える（コードの修正は不要） |
| Word のテンプレートの種類 | 1種類のみ（複数種類は後から追加） |
| Word に載せる項目 | 宛先・リリース形式の見出し、発信日（承認日）、ロゴ画像、タイトル、取材してほしい内容と社会的意義を含めた要旨（前文）、日時、場所、サービスや商品の概要、写真、会社の概要、会社情報（社名・住所）、お問い合わせ先（担当者名・電話・メール） |
| 要旨の元になる情報の入力 | 質問形式の入力欄を3つ（取材してほしい内容／なぜ今これを行うのか／伝えたいこと）。各欄500文字まで |
| 情報不足のときの確認 | 管理者が差し戻しに理由を書き、クライアントが追記して再提出する（F5b） |
| 想定する主な顧客 | 中小企業・個人事業主（広報担当がいない・少ない） |
| 本番の実行基盤 | Google Cloud の Cloud Run |
| 本番のデータベース | Cloud SQL（MySQL）。開発は SQLite |
| Word の雛形の置き場所 | プロジェクト内の templates フォルダに置き、Git で管理する。差し替えるときはファイルを入れ替えてコミット・デプロイする |
| 写真の枚数 | 1書類につき最大2枚。並べ方は仮に「本文の下に横並び」とし、雛形を作る時に確定する |
| 会社の概要の入力方法 | 会員情報に一度登録し、書類ごとに変更できる（初期値は会員情報の内容） |
| 固定文の文言 | 一般的な文言を仮置きして開発を進め、雛形を作る時に決める |
| 承認の目標期間 | 2営業日以内（目安。管理者が要旨を書く時間を含む。クライアントにも目安として表示。正式な約束ではない） |
| 承認待ちの管理者への通知 | 提出されたときにメールで知らせる（F25） |
| 音声入力 | 後回し。最初はテキスト入力のみ |
| 料金体系 | サービスごとの固定料金（金額は未定。下記の未決を参照） |
| 支払いのタイミング | 申込み時に前払い（Stripe Checkout） |
| キャンセル・返金 | 進捗に応じて一部返金。管理者が金額を決めて Stripe で返金する |
| 納期 | 注文ごとに管理者が納期日を設定し、クライアントに表示する |
| 「着手」の基準 | 管理者が進捗を「着手」に更新した時点（着手したら必ず更新する運営ルール） |
| 規約ページ | 利用規約・プライバシーポリシー・特定商取引法に基づく表記は、公開前に追加する。開発中は作らない |
| 返金の基準 | 進捗が「受付」=全額返金、「着手」=50%返金、「納品済み」=返金不可 |
| キャンセルの申し出 | 問い合わせ用メールアドレスへ連絡する（アプリ内にキャンセル機能は作らない） |
| 返金基準の表示場所 | サービス案内画面（申込み前）と注文確認メール |
| 管理者の編集の通知 | 承認時のメールとマイページで、要旨以外の項目の変更点（変更前→変更後）をクライアントに知らせる（要旨は管理者が書くため変更点には含めない）。承認前の個別通知や、クライアントの同意は求めない |
| 管理者の編集履歴 | 変更前後の内容を残す（release_edits）。承認後の書類は編集不可 |
| 退会 | 画面は作らず、問い合わせで受け付け、管理者が F21 で削除する |
| 退会時の個人情報 | 会社情報・作成済みの書類（Word・写真）・自社サービス入力・納品された記事ファイルを削除する |
| 退会の完了連絡 | アプリからは送らない。問い合わせメールへの返信で、管理者が伝える |
| 退会時の注文記録 | 個人情報を消して匿名化し、金額・日付などの記録は残す |
| パスワード再設定 | 最初のリリースに入れる（メールで再設定リンクを送る） |
| 会員登録時のメール認証 | 最初は不要。第2弾で追加 |
| 記事・動画の納品方法 | 記事はアプリ（管理者がアップロード → クライアントがダウンロード）。動画は外部リンク（限定公開など）で、リンクをアプリに登録して表示する |
| 動画作成の制作範囲 | 編集のみ。素材（写真・動画）はクライアントが提供する。撮影は含まない |
| 納品後の修正 | 1回まで無料。依頼は問い合わせメールで受け付け、管理者が注文に回数を記録する |
| 2回目以降の修正 | 有料。金額は個別に相談（アプリでの追加決済は作らない） |
| 動画の素材の渡し方 | 外部リンクで共有（クラウドストレージなど）。クライアントが申込み時に共有リンクを入力する |
| 動画の納品リンク | YouTube の限定公開リンク。管理者がアプリに登録する |
| 書類作成の無料範囲 | 総数（一生で）1件まで。設定で変更可能にする |
| 用語 | 「取材会の動向」は「同行」の誤記として扱う |
