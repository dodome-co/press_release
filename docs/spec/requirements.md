# 要件定義：プレスリリース作成支援アプリ「ゆきわり。」

詳しい仕様（入力項目の細かい決まり、決定済み・未決の事項）は [../仕様書.md](../仕様書.md) にある。このファイルは、その要点をまとめたもの。

## 1. 誰のために

| 利用者 | どんな人か | 困っていること |
| --- | --- | --- |
| クライアント | 東北の中小企業・個人事業主、新しく事業を始めた人。広報の担当者がいない、または少ない | プレスリリースの書き方と、新聞社・テレビ局への届け方（投げ込み）が分からない。CM や SNS に、お金や時間をかけている |
| 管理者 | 運営者（元新聞記者） | クライアントの入力をもとに、記者が取材したくなるプレスリリースに仕上げたい。注文の納期・納品・返金を、1か所で管理したい |

- 位置づけ：**ビジネスプランの発表用のデモ**。Google Cloud の VM に置き、発表の相手が自分の端末から触る。決済は Stripe のテストモードで、実際の請求はない。メールは実際には送らず、管理者の画面に記録する。

## 2. 何をするか

クライアントが、取材会の日時・場所・写真・伝えたいことなどを入力して提出すると、元記者の管理者が冒頭の要旨（前文）を書いて承認し、プレスリリースの PDF を受け取れる。プレスリリースの作成は1件目が無料で、2件目以降や、記者発表会の企画・同席、投げ込み交渉代行、記事・動画の制作は、有料で申し込める。

```
クライアントが入力・提出 → 管理者が要旨を書く・確認 → 承認すると PDF を出力 → クライアントがプレビュー・修正 → ダウンロード → 投げ込みガイドを見て届ける
```

## 3. コアの機能一覧

優先度：◎＝必須（実装済み）、○＝あると良い（実装済み）。ID は仕様書の機能要件と同じ。

### 3-1. 認証・会員

| ID | 機能 | 優先度 |
| --- | --- | --- |
| F1 | 会員登録（会社情報を含む）、ログイン、ログアウト。ロゴ・設立・資本金などは、あとからマイページで登録できる | ◎ |
| F1b | パスワード再設定（期限付き・1回限りのリンクをメールで送る） | ◎ |
| F2 | アクセス制御（ログインしていない人、ロールの違う人、他人のデータを見ようとする人を止める） | ◎ |

### 3-2. プレスリリースの作成（このアプリの中心）

| ID | 機能 | 優先度 |
| --- | --- | --- |
| F3 | 書類の入力：取材会の日付と時刻、場所を、フォームに入力する。サービスの内容と要旨の元になる情報は、AI とのチャットで答える（AI が足りない点を質問し、そろうと、タイトルの案・サブタイトル・特徴（最大3つ）・要旨・当日の対応者をまとめる）。タイトルとサブタイトルは、AI が、セットで3つの案を出し、管理者が選ぶ（タイトルは短めに。字数の制限はない）。特徴の見出しは、題材に合わせて、AI が決める（「アプリの特徴」「施設の特徴」「商品の特徴」など）。取材の申込方法と締切、当日のスケジュールは、聞かない・載せない | ◎ |
| F4 | 写真（1書類に2枚まで、横長だけ）とロゴのアップロード。形式と中身を検証する | ◎ |
| F5 | 画面で確認して「承認待ち」として提出する。下書きは3件まで持てる | ◎ |
| F5d | 無料で作れるのは1件まで。超えたら「リリース作成の追加」（1件4,000円）を案内する | ◎ |
| F5b | 管理者が、AI がまとめた内容を確認・修正し、承認または差し戻し（理由つき）をする。承認すると、クライアントのマイページに表示される。クライアントは、ダウンロードの前に、PDF をプレビューし、内容を修正できる（直すと PDF が作り直され、編集履歴に残る）。差し戻された書類は、クライアントが直して再提出できる | ◎ |
| F5c | 管理者が要旨（前文）を書き、ほかの項目も直せる。編集の履歴を残す | ◎ |
| F26 | 承認した時点で、内容と写真から、A4 1枚の PDF を作る（日本語フォントを埋め込み、1枚に収まるまで文字を小さくする。「取材のご案内」は、真ん中に寄せる）。承認後の修正でも、PDF を作り直す | ◎ |
| F6 | 承認された書類の PDF を、クライアントがダウンロードする（その前に、プレビューと修正ができる） | ◎ |
| F7 | 投げ込みガイド（会社の住所から都道府県を読み取り、その県の記者クラブへの届け方を表示する） | ○ |

### 3-3. 有料サービスと決済

| ID | 機能 | 優先度 |
| --- | --- | --- |
| F8 | サービスの一覧（内容・料金・注意書き）。ログインしなくても見られる | ◎ |
| F9 | サービスの申込み：リリース作成の追加、記者発表会の企画・当日の同席（地域で料金が変わる）、投げ込み交渉代行、記事制作、動画制作（媒体と長さを選ぶ） | ◎ |
| F11〜F13 | Stripe Checkout で支払う。支払いの確定は、画面ではなく Stripe からの通知（Webhook）で行う | ◎ |
| F14 | マイページで、注文の履歴・進捗・納期・納品物を見る | ○ |

### 3-4. 管理者の業務

| ID | 機能 | 優先度 |
| --- | --- | --- |
| F15 | 書類の一覧（承認待ち／承認済み／差し戻しで絞り込み）と詳細 | ◎ |
| F16・F19 | 注文の一覧と詳細。納期日の設定、進捗（受付→着手→納品済み）の更新 | ◎ |
| F22 | 納品：記事はファイルをアップロード、動画はリンクを登録する | ◎ |
| F20 | 返金：進捗に応じた上限（受付＝全額、着手＝50%、納品済み＝不可）の中で、Stripe で返金する | ◎ |
| F21 | 退会処理：会員の個人情報とファイルを消し、注文の記録は匿名にして残す | ○ |
| F17 | クライアントが入力した自社サービスの紹介を見る | ○ |
| F10 | （クライアント側）自社サービスの紹介を、文字で入力する（2,000文字まで） | ○ |

### 3-5. 通知

| ID | 機能 | 優先度 |
| --- | --- | --- |
| F25 | 書類が提出されたら、管理者に知らせる | ◎ |
| F18・F23 | 注文の確認、書類の承認・差し戻しを、クライアントに知らせる | ○ |

- デモでは、メールは送らずにデータベースに記録し、管理者の「送信予定のメール」の画面（`/admin/mails`）で見せる。

## 4. やらないこと

| やらないこと | 理由・代わりにどうするか |
| --- | --- |
| AI の案を、管理者の確認なしに確定すること | AI が、タイトルの案・サブタイトル・特徴・要旨・当日の対応者をまとめるが、確認・修正・承認は管理者（元記者）が行う。公開前には、クライアントの情報を外部のサービスに送ることを、プライバシーポリシーに書く |
| 音声入力 | 次の段階。今は、チャットの文字入力だけ（音声には、サーバーの HTTPS 化も要る） |
| クライアントが要旨（前文）やタイトルを書く | AI が案を作り、元記者の管理者が仕上げる。クライアントは、AI とのチャットで材料を出す |
| PDF のデザインを複数用意する | 1種類だけ。デザインを変えるときは、`app/pdfgen.py` を直す |
| Word（.docx）での出力 | PDF に変えた。Word の雛形は、なくした |
| 複数日にわたる取材会の日時入力 | 日時は1日だけ。複数日のときは、スケジュールや場所の欄で補足する |
| 縦長・正方形の写真 | PDF のレイアウトに合わせて、横長（横÷縦が1.2以上）だけ受け付ける |
| 画面からの管理者の作成 | 管理者は、コマンド `flask create-admin` でだけ作る |
| 1回の申込みで複数のサービスを頼む、8分以上の動画の申込み | サイト上では受け付けず、相談してもらう |
| 動画の撮影 | 動画制作は、預かった素材の編集だけ |
| 実際のメール送信、本番の決済（Stripe の本番モード）、HTTPS | デモのため、使わない。公開するときに、送信方法の選定、本番のキー、証明書を用意する（仕様書 9章の未決事項） |
| 一般への公開（事業としての運営） | 発表の相手だけが、合言葉つきで触れる。公開前に、利用規約・プライバシーポリシー・特定商取引法の表記が必要 |
| 取材の申込方法・締切、当日のスケジュール | 記者は、申し込みを嫌う。当日の流れは、要旨と日時・会場の説明で伝える。入力画面にも PDF にも出さない |
