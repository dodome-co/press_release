# 技術の説明メモ

デモ発表で「どんな技術を、どこで使っているか」を聞かれたときに、技術に詳しくなくても説明できるようにまとめたもの。

## 1. 全体像（最初に言う一言）

> 「Pythonで作ったWebアプリです。Google CloudのVM（仮想サーバー）の上で、データベースのMySQLと一緒に動いています。」

たとえるなら、次の対応。

- **Python / Flask** は、店の「スタッフ」。注文を受けて処理する。
- **MySQL** は、店の「帳簿」。会員、書類、注文を記録する。
- **VM** は、店の「建物」。24時間つけっぱなしのコンピューターを、Googleから借りている。
- **Nginx** は、店の「入口の受付」。合言葉を確認して、通った人だけをスタッフにつなぐ。
- **envファイル** は、店の「金庫」。パスワードやキーを、プログラムの外に、別に保管する。

## 2. 「なんていう技術を、どこで使っているか」

| 技術 | 何をするものか | このアプリでの使いどころ |
| --- | --- | --- |
| **Python 3.12** | プログラミング言語 | アプリ全体 |
| **Flask** | Pythonで、Webサイトを作る道具 | 画面の表示、ログイン、書類の提出と承認など |
| **HTML / CSS / Jinja2** | 画面の骨組み、見た目、HTMLの雛形 | `app/templates`（画面）、`app/static`（ロゴ、デザイン） |
| **MySQL 8** | データベース | 会員、書類、注文、メールの記録。VMの中で動く |
| **SQL** | データベースに命令する言語 | SQLAlchemy 経由で、間接的に使う |
| **Nginx** | Webサーバー | 外からの入口。合言葉（Basic認証）と、ファイルの受け取り |
| **gunicorn / systemd** | アプリを動かし続ける仕組み | gunicorn がアプリを実行し、systemd が VM の起動時に自動で立ち上げ、止まれば再起動する |
| **Google Cloud（Compute Engine）** | クラウドのコンピューター（VM） | 東京リージョンの Ubuntu 24.04。固定IPで公開 |
| **Git / GitHub** | ソースコードの履歴管理 | 変更の記録と、VM への配布 |
| **Stripe**（テストモード） | クレジットカード決済 | 申し込みの支払い。今回は見送り |

### envファイルについて

`/etc/press-release.env` に、次のような秘密の設定を書いている。

- アプリの暗号化キー
- データベースのパスワード
- Stripe のキー

コードの中には書かず、Git にも入れない。ファイルは、アプリ用のユーザーだけが読める権限にしてある。コードが漏れても、パスワードは漏れない作り。

### SQLについて

SQL を直接書かず、SQLAlchemy というライブラリ経由で、Python のコードから操作している。そのため、開発用の SQLite と、本番の MySQL を、同じコードで切り替えられる。今回は、全テストを MySQL でも通して確認した。

## 3. 「どんなライブラリを使っているか」

ライブラリとは、他の人が作った、便利な部品のこと。

| 分類 | ライブラリ | 役割（一言） |
| --- | --- | --- |
| Web | **Flask** | アプリの土台 |
| データベース | **Flask-SQLAlchemy** | Python の書き方で、データベースを操作する |
| | **Flask-Migrate**（Alembic） | データベースの構造の変更を、履歴として管理する |
| | **PyMySQL** | Python から MySQL につなぐ部品 |
| ログイン | **Flask-Login** | ログイン状態の管理 |
| 入力フォーム | **Flask-WTF** | 入力欄の検証と、なりすまし送信の防止（CSRF対策） |
| | **email-validator** | メールアドレスの形式の確認 |
| Word出力 | **python-docx / docxtpl** | Word の雛形に、入力内容を差し込んで、Word ファイルを作る |
| 画像 | **Pillow** | 写真の検証（横長か、大きすぎないか） |
| 決済 | **stripe** | Stripe との連携 |
| 公開 | **gunicorn** | アプリを本番で動かす |
| 設定 | **python-dotenv** | 設定ファイルの読み込み |
| 暗号 | **cryptography** | MySQL 8 の接続の暗号化に必要 |
| 開発 | **uv**、**pytest** | パッケージ管理、自動テスト |

## 4. 「コアになっている技術はどの部分か」

次の3つが中心。

1. **書類の作成から承認、Word出力までの流れ**（一番のコア）
   - クライアントが入力して提出し、元記者の管理者が要旨を書いて承認する。
   - 承認されると、Word の雛形（`templates/press_release.docx`）に、入力内容と写真が差し込まれて、プレスリリースの Word ができる。
   - 「元記者の目で仕上げる」という、サービスの価値を、仕組みにした部分。
2. **データの設計と、安全に管理する仕組み**
   - 会員、書類、写真、注文などを、MySQL の表に整理している。
   - パスワードは、そのままでは保存せず、暗号化した形（ハッシュ）で保存する。
   - ログインの失敗が続くと止める「回数制限」と、写真のアップロード検証も入れている。
3. **決済の仕組み（Stripe連携）**
   - 支払いの確定は、画面ではなく、Stripe からの通知（Webhook）で決める。
   - 返金も、管理画面からできる作り。今回は、見送っている。

## 5. 「品質をどう保っているか」

- 自動テストが約800件ある。SQLite と、本番と同じ MySQL の両方で、すべて通した。
- 設定は、開発、デモ、本番で切り替える。本番の設定が足りないと、アプリが起動しない作り。

## 6. 聞かれそうな質問と、答え方

- **「AIは使っていますか。」**
  今は、使っていない。要旨は、元記者の管理者が書く。次の段階で、Claude API を使って、要旨の下書きを作る機能を足す予定。
- **「なぜ、Flaskを選んだのですか。」**
  小さく始めて、必要なものを足していける、軽いフレームワークだから。
- **「データはどこにありますか。」**
  Google Cloud の東京の VM の中の MySQL。外からは、直接つなげない設定。
- **「セキュリティは、どうしていますか。」**
  入口の合言葉、アプリのログイン、パスワードの暗号化、回数制限、写真の検証を入れている。デモは HTTP なので、本物のパスワードを入力しないよう、画面にも書いてある。

## 注意

- 数字（約800件のテストなど）は、作成時点のもの。
- Stripe は、「仕組みは作ってあるが、今回は動かしていない」と、正直に話すのが安全。
