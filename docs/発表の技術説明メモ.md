# 発表の技術説明メモ（ねたもと。）

質問されたときに、答えるためのメモ。数字は 2026-11-21 時点。

## 1. ひとことで

地域の中小企業が入力した内容を、AI が聞き取り・下書きし、元記者の管理者が確認・承認して、プレスリリースの PDF にする Web アプリ。Google Cloud の VM で動かしている。

## 2. 全体の流れ

1. クライアントが、日付・時刻・場所をフォームに入力
2. AI とチャットで、「何を・なぜ・伝えたいこと」を話す（文字／音声）
3. AI が、タイトル＋サブタイトル3案・特徴・要旨・対応者を下書き
4. 写真を追加して提出
5. 元記者の管理者が、案を選び、要旨を直して承認
6. 承認した時点で PDF（A4 1枚）を作る
7. クライアントが、PDF をプレビュー・修正して、ダウンロード

## 3. 使っている技術

| 分類 | 使っているもの |
| --- | --- |
| 言語・Web | Python（開発 3.14、VM 3.12）、Flask 3、Jinja2 |
| データベース | 開発・テストは SQLite、VM は MySQL 8（Flask-SQLAlchemy、Flask-Migrate） |
| 認証 | Flask-Login、Flask-WTF（CSRF 対策）、パスワードはハッシュ |
| AI | Claude API（モデル `claude-opus-5-5`）。`app/ai.py` だけが呼ぶ |
| PDF | reportlab。日本語フォント（BIZ UDPゴシック）を埋め込み |
| 画像 | Pillow（形式・向き・大きさの検証） |
| 決済 | Stripe（作ってあるが、今回のデモでは動かさない） |
| 公開 | gunicorn、Nginx（合言葉の Basic 認証＋HTTPS）、systemd。証明書は Let's Encrypt（自動更新） |
| 開発 | uv、pytest（約900件）、GitHub Actions（MySQL でのテストを自動実行） |

## 4. AI の使い方

- **2種類の呼び出し**
  - 聞き取り（`interview`）：質問を返す。軽い設定で速い（3〜5秒）
  - 下書き（`compose`）：タイトル3案・特徴・要旨・対応者を作る。少し考えさせる（15〜20秒）
- **決まった形で返させる**（構造化出力 / JSON スキーマ）。文章をプログラムで読み取るのではなく、項目ごとに受け取る
- **事実を作らせない**：聞いていないことは書かない。日時・場所はフォームにあるので、聞き直さない。「取材の申し込み」には触れさせない（記者は嫌うため）
- **記者の経験はルールにする**：土日や午後遅い開始は、プログラム側で判定し、「平日の方が好まれますが、どうしますか」と聞く。社外秘の理由は、AI にもクライアントにも渡さない
- **AI の出力は、文字として表示する**（HTML として解釈しない）
- **安全装置**：書類ごとの呼び出し上限（30回）、回数制限、タイムアウト45秒、サーバー側のフォールバック指定
- **鍵の扱い**：`ANTHROPIC_API_KEY` は環境変数だけ。コードにも Git にも入れない
- **テスト**：AI は偽物に置き換え、実際には呼ばない（費用がかからない）
- **費用の目安**：1回のやり取りで数円、1件のリリースで数十円（見込み）

## 5. 人が判断するところ（品質の仕組み）

- 要旨（前文）は管理者が書く。空のままでは承認できない
- タイトル＋サブタイトルは3案から、管理者が選ぶ
- PDF は承認した時点で作る（提出時には作らない）
- 承認後の修正は、PDF が作り直され、編集履歴に「誰が直したか」が残る

## 6. PDF の作り方

- reportlab で、書類の内容から直接作る
- A4 1枚に収まるまで、文字を 1.0→0.7 倍へ、段階的に小さくする。それでも収まらなければ複数ページ（管理者の画面に表示）
- 空の項目は、見出しごと出さない。「◆ ○○の特徴」の見出しは、題材に合わせて AI が決める（アプリ／施設／商品 など）
- フォントを埋め込むので、相手のパソコンにフォントがなくても崩れない

## 7. 安全・権限

- ログインの入口は別：クライアントは `/login`、管理者は `/admin/login`。互いのアカウントでは入れない（エラーは同じ文言）
- 管理者は画面からは作れない（コマンド `flask create-admin` だけ）
- 他人の書類は、存在も分からないよう 404 を返す。下書きは、提出まで管理者にも見せない
- アップロードは、拡張子だけでなく中身も検証
- 決済の確定は、完了ページではなく Stripe の Webhook（署名を確認、同じ通知は2回処理しない）
- 秘密の値は、コードにも Git にも入れない（VM は `/etc/press-release.env`、権限 640）

## 8. 音声入力

- ブラウザの Web Speech API（Chrome / Edge）。サーバーには音声を送らない（文字にした結果だけ送る）
- 安全な接続（HTTPS）が必要。そのため、Let's Encrypt で HTTPS にした
- 音声で入力したときは、AI の返事を読み上げる。入力方法は `voice` として記録

## 9. 運用

- VM の更新：`sudo /opt/press-release/deploy/update.sh`（取り込み → `db upgrade` → 再起動）
- バックアップ：`deploy/backup.sh`（mysqldump）
- データベースの変更は、必ずマイグレーション。MySQL と SQLite の両方で通るように書く
- テストは約900件。MySQL でも全部通す
